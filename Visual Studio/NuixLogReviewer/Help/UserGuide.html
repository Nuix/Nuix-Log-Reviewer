Nuix Log Reviewer

A tool for triaging Nuix Workstation, Automate engine, Derby server, and Adaptive Security logs: search, visualize over time, group into recurring patterns, and surface notable findings.

Overview

The reviewer loads one or more log files into an in-memory, searchable index and presents them as a filterable grid with a timeline chart and several analysis tabs. Multi-line entries (e.g. stack traces) are kept together as a single entry.

The typical workflow:

  1. Load logs (a directory or individual files).
  2. Search / filter using the query bar, the level chips, or by hiding classifiers, files, and patterns.
  3. Visualize volume over time on the timeline; drag to zoom to a window, click to jump.
  4. Analyze — compute Patterns and Jobs, and run Insights for a list of "threads to pull on".
  5. Report — copy or save per-pattern summaries with real examples.
Whole-corpus vs. filtered. Most tabs reflect your current filtered view. Insights are the exception: they always analyze the whole loaded set, regardless of what you've hidden or searched.

Loading logs

MenuWhat it does

Loading a new set replaces the current session — the grid, patterns, jobs, insights, hidden sets, and history are all reset for the new corpus.

Recognized files & formats

A directory load includes files matching these name patterns, and skips the unstructured blobs stdout.log, stderr.log, derby.log:

  • nuix*.log* — Workstation / worker logs
  • automate-scheduler*.log*, automate-engine-server*.log*
  • engine.*-job.*.log*, engine.*-init.log* — Automate engine logs
  • derby-server*.log* — Derby network server logs
  • adaptive-prod-*.txt — Adaptive Security microservice / container logs

Each file's format is detected automatically by sampling its first lines, so different producers are parsed correctly without any per-file configuration. Supported formats:

  • Nuix / Automate / Derby — date time [channel] level source - message. The timezone offset and elapsed-milliseconds field are optional; the millisecond separator may be . (Nuix/Automate) or , (Derby, HH:mm:ss,fff).
  • Adaptive Security (.NET) — Kubernetes-prefixed lines of the form [date time LEVEL] source | message.
  • Adaptive Security (C++) — Kubernetes-prefixed date time LEVEL C:… P:… T:… message.

For the Adaptive formats, the leading Kubernetes/CRI transport timestamp is stripped from every line (including stack-trace continuation lines), and level names are normalized (e.g. EROR→ERROR, INFORMATION→INFO). Lines that don't start a new timestamped entry are treated as continuation content of the previous entry, so multi-line messages and stack traces stay together as one entry.

Searching

Type a query in the Query bar and press Enter (or click the magnifier). The query language is Lucene-style with a default field of content and a default operator of AND. Searches run in the background and can be cancelled from the busy overlay.

Additional quick filters compose on top of the query bar without editing it:

  • Level chips in the status bar — click INFO/WARN/ERROR/DEBUG to drill down to that level.
  • Eye toggles on the Classifiers, Files, and Patterns tabs — hide/show subsets of the current view.
  • The status bar shows filtered / total and an "N hidden by filters" indicator.

Query fields

ageVirtual field — time before the newest event (see below).age:24h
line, idLine number / entry id (numeric).line:1487

Combine with AND, OR, NOT and parentheses. Lower-case not is accepted and treated as NOT. A pure negation like NOT flag:worker_log returns everything not matching.

The age field

age is relative to the newest event in the loaded set. A single term means "at most this old"; a range narrows a window:

  • age:24h — events within the last 24 hours of the run.
  • age:[1h TO 3d] — between 1 hour and 3 days before the end.

Duration units: d days, h hours, m minutes, s seconds. A bare number is seconds.

Examples

level:error
level:(error OR warn)
flag:disk_space AND level:error
content:(timeout OR "connection refused")
timestamp:[638000000000000000 TO 638000000000009999]
age:4h
job:job-abcdef0123456789abcdef0123456789 AND level:error
Several ready-made searches ship under Searches › Append/Replace (e.g. Errors, Errors and Warnings, Age – Last 4h/24h). Save your own with Searches › Save Current Search As…

Find within results

The Find bar (beneath the query bar) marks — it does not filter — rows in the current set whose full content matches. Matching rows get a magenta dot in the leading column.

  • Regex and Case toggles.
  • Enter = next match, Shift+Enter = previous, Esc = clear. Prev/Next buttons do the same and wrap around.
  • The counter shows X of Y; navigation selects the matched row and scrolls to it.
Use the Query bar to choose which records are shown, and Find to locate specific ones within that set — e.g. pull in a time window for context, then find your seed event.

Results grid & Details

The grid lists matching entries with columns for File, Line, Time, an optional Δ (gap) column, Level, and Content. Rows are tinted by level (ERROR WARN INFO DEBUG). The File column shows a shortest-unique path tail (full path in the tooltip).

  • Time-gap cue (Settings › Time-gap cue) colors the line between rows by the time gap to the previous row, and/or shows a numeric Δ column. Tune the floor and highlight thresholds with the sliders.
  • Pivot Around Event Time… (right-click a row) reruns the search as a timestamp:[…] window around that event, keeping it selected — good for pulling in surrounding context.
  • Selecting a row opens the Details tab: all fields, assigned classifier flags (with descriptions), the full content, and a Copy Log Line button that copies the reconstructed line.

Timeline chart

The strip under the grid charts INFO/WARN/ERROR volume over the current set's time span as a stacked density bar.

  • Drag horizontally to zoom the search to that time window.
  • Click to scroll the grid to the nearest event at or before that time (doesn't change the search).
  • Hover for a timestamp readout. A marker shows the selected row's time; a shaded band shows the currently-visible rows.
  • Log toggle (top-right, on by default) log-compresses bar heights so small/rare buckets stay visible next to a very tall one (e.g. a spike of errors next to a wall of retries). Uncheck it for linear heights when you care about relative volume.
  • Job lanes — when Jobs are computed and "Show on timeline" is on, worker job lifespans are drawn as brackets above the bars; selecting a job in the Jobs tab emphasizes its bracket.

Analysis tabs

Classifiers

Lists the classifier flags present in the loaded set with counts and descriptions. Classifiers are rules that tag entries (e.g. disk_space, null_pointer). Use the eye to hide/show a flag's entries in the current view, Hide all / Show all for bulk changes, or double-click to drill to flag:<name>. Counts reflect the whole set, so hidden flags still show their true totals.

Files

Lists the source files with counts. Eye-toggle to hide/show a file, or double-click to drill into just that file. Names are shortest-unique tails (e.g. worker-1/nuix.log).

Patterns

Compute Patterns groups the current set into normalized message templates — variable parts (ids, paths, numbers, …) are masked so recurring shapes collapse together. This surfaces both high-volume noise and rare one-offs. Default sort is by count ascending, so the rarest patterns are at the top.

  • Eye hides/shows a pattern's entries in the main view; the listed counts stay as-of the last Compute (a stale hint reminds you to recompute).
  • Expand by (Worker / Exception / Sub-template) then click a row's expander to break that pattern into sub-patterns — e.g. by which worker produced it, or which exception it carries. Double-click a sub-pattern to drill into just those entries.
  • Double-click a pattern to show exactly its entries in the grid.

Copy / export a summary (right-click selected patterns): each option produces a per-pattern report with the matched template, counts, the files it appears in, and one real example line in a monospace block.

OptionBest for
Copy Summary (rich + Markdown)Pasting into Word / Outlook / Confluence (rich HTML) or a Markdown doc.

Jobs

Compute Jobs groups worker entries by job id and shows each job's lifespan (first/last event), entry/warn/error counts. Double-click to drill to job:<id>; selecting a row highlights the job on the timeline.

Insights

Analyze scans the whole loaded corpus and lists notable findings — "threads to pull on" — grouped by source. Each finding has a severity (Critical Warning Notice Info) and, usually, a ready-made query. Double-click a finding to run its query and jump to the evidence.

Built-in detectors cover error spikes, error-heavy files, troubled jobs, notable/rare patterns, silence gaps, error trends, first errors, out-of-memory, GC pressure, disk space, and throttling/retries (see below). You can add your own — see Scripted insights.

History & saved searches

  • Back / Forward (or Alt+← / Alt+→) move through your view history — each step remembers the query, hidden sets, and grid position.
  • Searches › Save Current Search As… stores the current query by name; Append ANDs a saved query onto the current one, Replace swaps it in.
  • The status-bar Range label shows the current set's time span; click it to copy.

Configuration

Editable configuration lives in a Configuration folder next to the application (open it via Settings › Open Configuration Folder):

PathPurpose
LogPatterns.configPattern-masking rules & grouping.
ClassifierVisibility.configPer-flag default show/hide.
SavedSearches\*.txtSaved searches (filename = name, contents = query).
ClassifierScripts\*.jsScripted classifiers.
InsightScripts\*.jsScripted insight detectors.
LogPatterns.config and scripted classifiers are read once at startup, and templates are computed at index time — so after editing them you must restart and reload the logs. Insight scripts are re-read on every Analyze.

LogPatterns.config

One directive per line; blank lines and # comments are ignored. Rules apply top-to-bottom (most specific first):

# Mask a variable part to a token:
<regex> => <token>

# Collapse a known-noisy family by its first-line prefix (case-sensitive):
GROUP=Invalid cookie header:

# Exception-aware templating (default on): append the first Java throwable
# class + message so same-shape/different-exception errors don't merge.
EXCEPTIONS=on

Built-in tokens include <GUID>, <EMAIL>, <PATH>, <URL>, <IP>, <TS> (timestamps), <ID> (hex ids), <SLACKID>, <OBJ> (Java object refs), /<FILE>, '<KEY>' (config keys), #U (number+unit) and # (bare number). Templates are built from the first line, whitespace-collapsed and length-capped.

Classifier visibility

Settings › Classifier Defaults… sets which classifier flags are shown or hidden by default on load (written to ClassifierVisibility.config as <flag> = shown|hidden). This affects the next load; per-session eye toggles are independent.

Extending the app

Scripted classifiers

Drop a .js file in Configuration\ClassifierScripts\. The script evaluates to an object exposing classify(entry) that returns a flag string, an array of strings, or nothing:

({
  name: "My rule",
  // optional: only run when content/source contains one of these (fast pre-filter)
  prefilter: ["timeout", "socket"],
  // optional: flag -> description shown in the Classifiers tab
  descriptions: { my_timeout: "A network timeout." },
  classify: function (entry) {
    if (entry.content.indexOf("SocketTimeoutException") >= 0) return "my_timeout";
    return null;
  }
})

The entry exposes read-only content, source, level, channel, filePath, fileName, timeStamp (ISO string), elapsedMs, and lineNumber. Scripts run in a sandbox (no filesystem/network, time- and statement-limited); a misbehaving script is disabled for the session and reported. Flags become searchable as flag:<name>.

The app ships adaptive_security.js, which tags common Adaptive Security service failure modes: adaptive_state_transition, adaptive_enrich_failure, adaptive_es_bulk_failure, adaptive_kafka_topic, and adaptive_kafka_poll. Edit or copy it as a template for your own service signals.

Scripted insights

Drop a .js file in Configuration\InsightScripts\ (see the shipped example_insight.js). The script exposes analyze(ctx) returning an array of findings:

({
  name: "Custom",
  analyze: function (ctx) {
    var out = [];
    ctx.patterns.forEach(function (p) {
      if (p.error > 100) out.push({
        severity: "warning",           // info | notice | warning | critical
        title: "High-volume error pattern",
        detail: p.count + " lines: " + p.template,
        query: p.query                 // precomputed, ready to run
      });
    });
    return out;
  }
})

ctx exposes whole-corpus data: scalars (total, info, warn, error, debug, minTicks, maxTicks) and arrays flags, files, jobs, patterns. Every item carries a precomputed, correctly-escaped .query you can hand straight back as a finding's jump target. A finding needs at least a title; query, positionEntryId, and positionTicks are optional. Insight scripts are re-read on each Analyze.

Built-in classifiers & insights

Classifier flags shipped with the app include: disk_space, memory, worker_state, multi_line, script, worker_log, nuix_package, process_killed, problem_processing_item, session_is_closed, null_pointer, http_forbidden, http_unauthorized, http_timeout, connection_refused, engine_comm_failure, engine_load_failure, license, third_party_rest, oidc_sync_failure, google_oidc.
